# Mandyal Tour & Travel — MERN site with SEO foundation

## ⚠️ Read this first

The uploaded zip (`stitch_dutta_motors_landing_page.zip`) contained only a
single static HTML mockup (desktop + mobile) generated by Stitch, plus a
design-token file — there was no pre-existing MERN app (no React/Node/Express
project, no routing, no database, no admin panel). Per your instruction, this
whole MERN application — frontend, backend, routing, database models, and the
full SEO layer — was **built from scratch**, reusing every real piece of
business content, fleet, tour-package and destination data that was actually
present in the mockup (nothing was invented).

**I could not run `npm install` or a build in the environment I wrote this
in — it has no network access.** Every file here was hand-written and
reviewed for correctness, but you (or your CI) must run the install/build
steps below to confirm it compiles, before treating this as done.

## 1. Setup

### Quick Start (Monorepo root)

```bash
# 1. Install all dependencies across client and server
npm install

# 2. Configure server environment
cd server && cp .env.example .env && cd ..

# 3. Seed initial real data (optional, requires MongoDB)
npm run seed

# 4. Start both Server (:5000) and Client (:5173) concurrently
npm run dev
```

### Individual Service Setup (Optional)

```bash
# Backend
cd server
cp .env.example .env      # then edit ADMIN_API_TOKEN, MONGODB_URI, SITE_URL
npm install
npm run seed               # seeds the real tour/destination records (no fake articles)
npm run dev                # http://localhost:5000

# Frontend (separate terminal)
cd client
npm install
npm run dev                 # http://localhost:5173 (proxies /api, /sitemap.xml, /robots.txt to :5000)
```

Production build:

```bash
cd client && npm run build   # outputs client/dist
cd ../server && npm start    # serves client/dist + API + sitemap/robots on one port
```

Before deploying, update `SITE_URL` in `server/.env` and `siteUrl` in
`client/src/data/business.js` to the real production domain.

## 3. SEO features implemented

- Unique `<title>` and meta description per page via a shared `SEO`
  component (`react-helmet-async`).
- Self-referencing canonical URL per page, trailing slashes normalised.
- `robots` meta: `index, follow` on all public pages; `noindex, nofollow` on
  `/admin/articles`.
- Open Graph (`og:title`, `og:description`, `og:image`, `og:url`, `og:type`)
  and Twitter/X card tags on every page; `og:type=article` on Travel Guide
  articles.
- `<html lang="en">`.
- Exactly one `<h1>` per page.
- `alt` text on the article featured image and fleet imagery slots (no
  keyword stuffing); images use `loading="lazy"` and explicit
  width/height/aspect-ratio where added.
- Internal linking: homepage links to all 12 other pages, including the two
  required links (Amb → `/taxi-service-amb` in the Local Service Areas
  section, Amb Andaura Railway Station → `/amb-andaura-railway-station-taxi`
  in the Railway Transfers section). Amb page links to the railway station
  page, outstation taxi, destinations and contact; the railway station page
  links back to Amb, outstation taxi and contact; the Una page links to Amb,
  the railway station, outstation taxi and destinations.
- Breadcrumbs (visible UI) + `BreadcrumbList` JSON-LD on every page below
  Home.
- `TaxiService`/`LocalBusiness` JSON-LD sitewide, using only verified fields
  (name, telephone, email, address, url) — no invented ratings, price range,
  opening hours, founding date, or geo-coordinates.
- `BlogPosting` JSON-LD on Travel Guide articles, generated from real
  admin-entered fields (no fake data).
- Dynamic `/sitemap.xml` (Express route) covering all static pages, the 8
  route-taxi pages, and published Travel Guide articles — no admin, API, or
  duplicate URLs included.
- `/robots.txt` allowing public pages, disallowing `/admin` and
  `/api/admin`.
- A real 404 page (not a redirect) with navigation back into the site.
- Data-driven SEO: Travel Guide articles carry `seoTitle`, `seoDescription`,
  `canonicalUrl`, `ogImage`, `slug`, `h1`, `description` fields, editable via
  the admin API — nothing hardcoded per-article.

## 10. Remaining tasks that need your input / external setup

- **Verify the build actually compiles.** I could not run `npm install` or
  `vite build` in this environment (no network access) — run it yourself
  before deploying, and fix any dependency-version mismatches that turn up.
- **Set the real production domain** in `server/.env` (`SITE_URL`) and
  `client/src/data/business.js` (`siteUrl`) — I used a placeholder.
- **Client-side rendering limits SEO.** This is a Vite SPA: crawlers that
  don't execute JavaScript will see the fallback tags in `index.html` before
  React/Helmet swap in the real per-page tags. Most major crawlers do render
  JS today, but for stronger guarantees consider adding a prerendering step
  (e.g. `vite-plugin-ssr`, `react-snap`, or a dedicated SSR framework) later.
- **Real `og-default.jpg` and per-page/per-article OG images** — none were
  supplied, so `SEO.jsx` falls back to `/og-default.jpg`, which doesn't exist
  yet. Add real images.
- **Harden `/admin/articles`.** The bearer-token check is a starting point,
  not production auth — add real login, and make sure `/admin` is not
  reachable by search engines (already `noindex`, but also keep it off any
  public site navigation).
- **Google Search Console / Bing Webmaster Tools** — submit the sitemap once
  live; register the property; this can't be done from inside the codebase.
- **MongoDB hosting** — set `MONGODB_URI` to a real instance (Atlas or
  self-hosted) for Travel Guide articles to work in production.
- Travel Guide currently has **zero articles** — intentionally, since none
  existed in your source content and none should be invented. Publish real
  ones via `/admin/articles` once you have content and an `ADMIN_API_TOKEN`.

This gives you a technically strong, locally relevant, crawlable SEO
foundation — it does not and cannot guarantee search rankings.
